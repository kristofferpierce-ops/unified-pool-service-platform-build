# Phase 22 Step 28 - Phase 20 Network Transport Planning Pattern Detection Alignment Packet

## Purpose

This packet continues the Phase 22 planning-only sequence after probabilistic calibration alignment.

Phase 22 Step 28 records how future pattern detection should align with the connector-first operating core, source-bucket discipline, canonical event ledger planning, expected-vs-actual variance planning, driver attribution planning, and probabilistic calibration planning.

This is not an implementation step.

## Pattern detection scope, planned only

Future pattern detection should eventually help identify:

- profitable account classes
- unprofitable pool types
- route inefficiencies
- high-cost equipment families
- costly customers with slow payment behavior
- jobs that look profitable but lose money through callbacks or labor drag
- chemical usage anomalies
- labor-minute anomalies
- vendor price variance
- branch-specific margin drift
- seasonal anomalies
- route-density expansion signals
- retreat signals for high-noise, low-margin account categories

Phase 22 Step 28 does not implement any of those detectors.

## Bridge absorption guardrail

The bridge remains a source and workflow module that should eventually be absorbed as connector packages and front-desk workflow modules.

This step does not merge the bridge DB into the platform DB.

This step does not change the bridge route surface.

This step does not create bridge write behavior.
