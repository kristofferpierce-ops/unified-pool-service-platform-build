# Adversarial Review: QuickBooks Universal Translator Design

Verdict: the no-loss *byte* spine is sound, but the design has confirmed holes in three places the mandate cares about most â€” **cross-tier double-counting of cost**, **validation that proves bytes survived but not that meaning is correct**, and **uncertain/failure cases that still have no terminal home**. Ranked by severity.

## A. CONFIRMED double-counts (the "no double-counting" mandate is violated as written)

**1. Field-tech labor is counted twice: Tier 1 overhead + Tier 4 burdened wage.** Verified in code: `cost_of_business.py:101` computes `true_cost = burdened_wage + overhead_per_hour`, and `expenses.py:14-15` `annual_overhead_total` sums **every** `ExpenseItem.annual_cost` with no category filter. `bootstrap.py:23-24` already seeds `management_admin_labor` and `bookkeeping_payroll` *as ExpenseItem rows*. So Tier 1 (which loads P&L `EXP` accounts, including Wages/Payroll-Tax accounts, into `ExpenseItem`) puts labor into `overhead_per_hour`; Tier 4 then puts the same labor into `LaborSettings` â†’ `burdened_wage`. The sum counts labor once in each. The design's Tier 4 "split field vs admin" note gestures at this but never states the rule. **Fix:** Tier 1 must EXCLUDE wage + employer-payroll-tax `EXP`/`COGS` accounts from the `ExpenseItem` overhead spine (they belong to `LaborSettings`/`PayrollRun`, not overhead); add an explicit account-classification tag `is_labor_account` so a payroll account can never land in `annual_overhead_total`. Add a validation that no ExpenseItem overhead row and no LaborSettings wage derive from the same QB account.

**2. Tier 1 report facts and Tier 3 IIF facts double-count the same period.** Â§3.4 guard #2 says "never ingest both an IIF and a GL/P&L report of the same period into facts," but the tier plan does exactly that: Tier 1 lands report-level `EXP`/`EXEXP` totals into `ExpenseActual` (facts, applied, owner-signed-off), then Tier 3 lands IIF line-level cost into `Bill`/`BillLine`/`ProductPriceHistory` (facts) for the same accounts and periods. `ExpenseActual` and `BillLine` are different tables but both feed cost/profitability. There is no supersede mechanic. **Fix:** define an explicit source-of-truth election *per account Ã— period*: when Tier 3 IIF detail exists for an (account, period), it SUPERSEDES the Tier 1 `ExpenseActual` row for that cell (mark superseded, don't sum); the cost-of-business aggregation must read at most one source per (account, period). Add a reconciliation assert that Î£(ExpenseActual not-superseded) + Î£(BillLine) has no overlapping (account, period).

**3. Depreciation is double-counted between Tier 1 and Tier 5.** Depreciation typically posts to an `EXP`/`EXEXP` account, so Tier 1 already captures it in the P&L totals. Tier 5 then "ingest depreciation JEs â†’ CompanyAsset + depreciation period cost" re-adds it. **Fix:** Tier 5 depreciation must reconcile to (not add on top of) the depreciation expense account already in Tier 1; ingest the JE for *asset attribution/dimensioning* only, and assert Î£(Tier 5 depreciation) == the depreciation `EXP`/`EXEXP` account total already loaded, rather than creating new cost.

**4. Admin/employer-tax payroll double-counted between Tier 1 and Tier 4.** Same root as #1 but for admin: Tier 1 loads the "Payroll Taxes" / "Admin Wages" `EXP` accounts into `ExpenseItem`; Tier 4 also writes admin payroll into `ExpenseItem` overhead rows (`management_admin_labor`, `bookkeeping_payroll`). Without dedup these stack. **Fix:** elect one payroll source (Payroll Summary/PAYCHECK detail is authoritative); Tier 1 must not load payroll-typed accounts into `ExpenseItem` at all; add the same (account,period) supersede guard as #2.

**5. `Total <Parent> including subaccounts` roll-up is unmapped â€” a named double-count hazard (schema #5).** Â§2.6 handles `Total <account>` but never the parent-including-subaccounts roll-up, which sums children. If the classifier treats it as another `Total` control row and the tie-out sums both child totals and the parent-including total, cost doubles. **Fix:** add a distinct classification `subtotal_parent_rollup`, exclude it from every fact and control-total sum, and in the Â§6 tie-out compare imported-per-leaf-account only to leaf `Total <account>`, never to the roll-up.

**6. `AMOUNT/QNTY` unit-cost division has no sign guard and no zero/null guard.** Â§2.5 sets `ProductPriceHistory.unit_cost = AMOUNT/QNTY`. On purchases QNTY sign is unspecified (schema says QNTY is negative on *sales*), so a negative QNTY flips unit_cost negative; QNTY blank/0 (expense-tab lines, service items) divides by zero. Result: negative or infinite unit costs silently overwrite good price history. **Fix:** compute `unit_cost = abs(AMOUNT)/abs(QNTY)` only when QNTY is present and non-zero; when QNTY is 0/null, route to `needs_review` (no unit cost derivable), never write a 0 or inf.

## B. Validation proves bytes, not meaning (silent semantic loss goes undetected)

**7. The Â§6 round-trip proves byte survival but NOT correct cell segmentation.** A row can round-trip `raw_line_text` perfectly while every cell is assigned to the wrong column (layout misdetection: Debit/Credit vs single Amount, wrong delimiter, shifted header). The whole apply is then wrong yet all Â§6 asserts pass. This is the biggest hole in the guarantee â€” "understand before applying" is unverified. **Fix:** add a cell-level validation: (a) re-serialize `RawSourceCell`s with the detected delimiter/quoting and assert it reconstructs `raw_line_text` exactly; (b) assert every data row's cell count == active header column count (IIF hazard #26) or quarantine; (c) numeric-column cross-foot: Î£ of the parsed money column per band == the band's captured `Total` control row (already partly in step 5) â€” make this a hard gate, not owner-eyeball.

**8. The "byte-exact" round-trip is actually a *decode* round-trip â€” encoding misdetection is invisible.** Â§6 step 2 diffs "after encoding-decode," so both sides use the same (possibly wrong) codec and a CP-1252/UTF-8 mojibake on a middle-dot or curly quote passes silently. **Fix:** anchor the round-trip to raw BYTES against `file_sha256` (re-encode reconstructed rows and compare byte-for-byte, or store per-row byte offsets), and detect encoding failure explicitly (presence of U+FFFD replacement char, or bytes that don't round-trip through the chosen codec â†’ quarantine the artifact, don't proceed).

**9. Decimal vs float, and no tie-out tolerance.** Â§6 asserts exact equality (`TRNS.AMOUNT + Î£SPL.AMOUNT = 0`, `Î£ imported == Total<account>`). If implemented in float, penny drift silently corrupts; if exact on legitimately-rounded cross-export comparisons, it cries wolf and blocks. **Fix:** mandate `Decimal` throughout the money path; define exact-zero for the intra-file IIF zero-sum, and an explicit tolerance (e.g., Â±$0.01 Ã— line count) for cross-export report-vs-IIF tie-outs, with any breach routing the *specific* offending block/account to quarantine (not halting the whole ingest).

**10. No full P&L closing-identity reconciliation â€” an entire section can be missed undetected.** Â§6 ties expenses to `Total Expenses` and revenue to `Total Income` separately, but never asserts the closing identity `Total Income âˆ’ Total COGS âˆ’ Total Expenses âˆ’ Total Other Expense + Total Other Income = Net Income`. Without it, a whole missed section (e.g., `Other Expense`, or `COGS` on the report path which Tier 1 omits â€” see #16) is not caught. **Fix:** capture every section control total and assert the classified sum (cost + excluded-revenue + excluded-capital) reproduces the report's `Net Income` control row. Every dollar on the statement must land in exactly one bucket and the buckets must close to Net Income.

**11. Unreviewed backlog silently deflates the cost number (skimmer failure reincarnated at the aggregate).** `needs_review`/`quarantined_*` rows are persisted (good for no-loss) but never applied, so `true_cost_per_hour` silently omits them. A pile of unmatched material cost stuck in review understates cost with no signal. **Fix:** the reconciliation dashboard must show, per status, the DOLLAR value and % of total classified cost sitting un-applied; the owner sign-off gate (Â§6 step 10) must display "cost-per-hour excludes $X (Y%) still in review" and refuse "live" status while un-applied cost exceeds a threshold.

**12. High-confidence (â‰¥0.90) matches auto-apply with no first-sight confirmation or sampling.** A wrong-but-confident vendor/customer/item match misattributes cost to the wrong entity, corrupting per-customer/route margin â€” a semantic loss the byte round-trip can't see. Â§5 confirms "first import of each account" but not each vendor/customer/item. **Fix:** the FIRST time a given external entity resolves (new `ExternalIdentityMap` mint), surface it for one-time confirmation even at â‰¥0.90; thereafter auto-apply. Add a reconciliation sample of N auto-matches per import for owner spot-check.

## C. Uncertain / failure cases with no terminal home (violates I2)

**13. A failing zero-sum block has no defined outcome.** Â§2.5/Â§6 "assert `TRNS.AMOUNT + Î£SPL.AMOUNT = 0`" but never says what happens on failure. An assert that halts violates no-loss (aborts ingest); one that only logs may apply the imbalanced block. **Fix:** on zero-sum failure, quarantine the ENTIRE block (`quarantined_parse`, reason `iif_block_unbalanced`) â€” never drop, never apply, never halt the batch.

**14. Malformed block structure (orphan SPL, missing ENDTRNS, field-count mismatch) has no status.** Statuses cover ambiguous layout but not structural IIF breakage (hazards #26, #28). **Fix:** add reasons `iif_orphan_split`, `iif_unterminated_block`, `iif_field_count_mismatch` under `quarantined_parse`.

**15. Any exception in `classify()`/`interpret()` is an uncaught silent drop.** The design guarantees "every RawSourceRow gets exactly one interpretation record" but doesn't mandate that a thrown exception (unparseable date, div-zero from #6, bad Decimal) lands the row in quarantine rather than aborting the pass or skipping. **Fix:** wrap each row's classify/interpret in a try/except that writes `quarantined_parse` + the traceback and continues; a per-artifact assert that interpretation-record count == RawSourceRow count is the enforcement.

**16. Tier 1 omits COGS accounts, so the cost-per-hour signed off at Tier 1 is structurally incomplete.** Tier 1 ingests only `EXP`/`EXEXP`. A pool company's chemical/direct-labor/subcontractor cost sits in `COGS`, which arrives only in Tiers 2-4. The owner signs off (Â§6 step 10) on a `true_cost_per_hour` that excludes all direct cost. **Fix:** either include `COGS` account totals in Tier 1, or explicitly label the Tier 1 sign-off "overhead-only, provisional â€” direct cost pending Tier 2-4" so the owner isn't accepting a wrong number as final.

**17. Tier 1 applies known-lossy report facts before the authoritative IIF source is ingested (Tier 3).** The design's own recommendation prefers IIF; yet Tier 1 applies report-derived cost that Tier 3 will supersede, with no defined migration. This is "apply before fully understood." **Fix:** mark all Tier 1 facts `provenance=report_provisional`; when Tier 3 IIF arrives, run the supersede path from #2; never let a report-provisional fact and an IIF fact for the same (account,period) both count.

## D. Unmapped columns / silent-drop surface (the "not one word" claim overstated)

**18. Â§2.8's claim "every column named in the schema report has a row above" is false.** Not enumerated: `!VEND` `SALUTATION/FIRSTNAME/MIDINIT/LASTNAME/NOTE`; `!INVITEM` `TAXABLE/SALESTAXCODE/DEP_TYPE/CUSTFLD1..5/HIDDEN/DELCOUNT`; `!CUST` `SADDR*`. They fall to the CTX safety net (preserved), so no *byte* loss â€” but the coverage claim is inaccurate and two are load-bearing: `FIRSTNAME/LASTNAME` matter for a vendor that has only a person name (no COMPANYNAME) in resolution; `HIDDEN` matters so inactive items/accounts don't fuzzy-match live products. **Fix:** enumerate these explicitly; use FIRSTNAME/LASTNAME as a resolution fallback when COMPANYNAME is blank; exclude `HIDDEN=Y` masters from auto-match (route to review).

**19. `!EMP` has no field-by-field mapping, and `SSNO` (SSN) is stored verbatim in plaintext.** I1 mandates every byte verbatim, so SSNO lands in `raw_line_text` and `RawSourceCell.raw_value` unencrypted. This is a privacy hole with no decision. **Fix:** add an `!EMP` mapping; designate SSNO (and any TAXID) as a sensitive field that is preserved-but-encrypted-at-rest (or tokenized with the hash kept for round-trip), so no-loss holds without leaking PII into every query surface.

**20. Payroll-pivot internal subtotals ("Total Gross Pay", "Adjusted Gross Pay", "Total Taxes Withheld", "TOTAL" column) are a double-count hazard not called out.** Â§2.7 maps component rows but not the pivot's own subtotal/total rows. Summing components + subtotal double-counts wages; `Adjusted Gross Pay` (gross minus pre-tax deductions) summed with `Gross Pay` double-counts. **Fix:** classify pivot subtotal rows and the `TOTAL` column as control-totals (reconciliation only, never summed); treat `Adjusted Gross Pay` as a derived check, not an additive earnings row.

**21. Non-cost item types (DISC/SUBT/GROUP/PMT/STAX) and `%`-valued discount items are unmapped.** Â§2.4 covers SERV/NONINVPART/INVENTORY/OTHC only. A `%` in the Cost/Price cell breaks decimal parse; group/subtotal items have no cost account. **Fix:** classify these INVITEMTYPEs `excluded_by_type` (reason `non_cost_item_type`) so they don't clutter `quarantined_unmapped` and a `%` value never reaches the numeric parser.

**22. Report running-`Balance` column disposition is unspecified.** If layout detection misfires, the running Balance could be read as the transaction Amount. **Fix:** explicitly mark the report `Balance` column CTX/reconciliation and assert it is never the money column feeding facts.

## E. Raw-preservation / idempotency holes

**23. `file_sha256` dedup never fires on real re-exports, so re-imports can double-count.** QuickBooks stamps `!HDR` DATE/TIME on every export, so a re-export of the same period is byte-different â†’ sha256 won't dedup, and idempotency then rests entirely on `ExternalIdentityMap`. But IIF `TRNSID`/`SPLID` are often blank, leaving no natural key. **Fix:** define a composite transaction identity when TRNSID is absent (hash of date + docnum + account + amount + memo + line-ordinal); dedup on that. State clearly that `file_sha256` catches only identical re-uploads, not re-exports of the same data.

**24. Re-parse after apply orphans `ApplyEvent`/`ExternalIdentityMap`.** Â§1.3 says "delete all normalized rows and rebuild" is "always safe," but if those rows were applied, deletion breaks the ApplyEvent linkage and new surrogate ids won't match the old ExternalIdentityMap. **Fix:** block re-parse when applies exist against the artifact, or re-key ExternalIdentityMap by natural key (#23) so rebuilt rows re-link deterministically; add a test that re-parse-after-apply produces zero new applies.

**25. No periodic integrity check on stored artifact bytes.** The rebuild-from-bytes guarantee dies silently if a file under `UPLOAD_DIR` is later moved/corrupted; nothing re-hashes stored files vs `file_sha256`. **Fix:** add a scheduled integrity sweep that re-hashes every `SourceArtifact.file_path` against `file_sha256` and alarms on mismatch/missing.

## F. Semantic hazards with no guard

**26. Cash vs Accrual basis is captured but never enforced as consistent.** A Cash-basis P&L (excludes unpaid bills) reconciled against an Accrual IIF (includes them) will mis-tie or double-count across the bill/payment timing. **Fix:** make basis a first-class dimension; refuse to reconcile or aggregate artifacts of mixed basis for the same period; every tie-out must be basis-scoped.

**27. Date-locale is assumed US MM/DD/YYYY with no validation.** A DD/MM file silently transposes dates (cost lands in the wrong period â†’ wrong trailing-12-month and wrong period tie-out). **Fix:** derive expected locale from the report title-block date range, validate against values (day>12 disambiguates), and quarantine ambiguous dates rather than guessing.

**28. Voided / zero-amount transactions have no handling.** A voided bill (AMOUNT 0, may retain QNTY) would pass as a `ready` $0 cost line and can overwrite `ProductPriceHistory` with 0, or trigger the #6 div-by-zero. **Fix:** classify AMOUNT==0 and memo-prefixed `VOID:`/`VOIDED` transactions as `excluded_by_type` (reason `voided_or_zero`), and never let a zero-amount line write unit cost.

**29. GL Debit/Credit â†’ signed-amount conversion is underspecified (sign-flip risk).** Â§2.6 says amounts are "normalized" but never states the per-normal-balance rule `signed = Debit âˆ’ Credit` for debit-normal cost accounts. A naive `Credit âˆ’ Debit` flips every cost negative. **Fix:** state the rule explicitly and key it to the account's normal balance (from `LedgerAccount.account_type`); add a sanity assert that on a `COGS`/`EXP` band the net signed sum is positive (costs), flagging bands that come out net-negative to review.

**30. Colon-in-name ambiguity for accounts/customers/classes has no review path (hazard #30).** A literal colon inside a real name silently mis-parents the hierarchy. **Fix:** when a colon-split yields a parent segment not present in the already-ingested masters, route to `needs_review` (reason `ambiguous_hierarchy`) rather than auto-creating a phantom parent.

---

**Bottom line for the owner's mandate:** the verbatim byte spine (I1) and the type-first exclusion whitelist (I3) are solid and the code references are all accurate. But as written the design (a) **double-counts labor, depreciation, and any account that appears in both a report tier and the IIF tier** â€” findings #1-4 are confirmed against `cost_of_business.py`/`expenses.py`/`bootstrap.py`, with #1 being a certain labor double-count; (b) **validates that bytes survived but not that cells/meaning are correct** (#7-8), so a whole-file misparse passes every current check; and (c) still has **uncertain and failure cases (#13-15, 30) that can drop an interpretation** despite the I2 promise. Fix the (account, period) source-of-truth election and the labor/overhead exclusion first â€” those are where the "no double-counting" mandate actually breaks today.
